# cccc v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task.

**Goal:** Ship a standards-compliant, testable cccc v2 skill whose delegate and consult wrappers have safe defaults, fresh atomic outputs, reliable timeouts, and an explicit v1 migration path.

**Architecture:** Keep the installable skill entirely under `skills/cccc/`. Put cross-wrapper validation and Git policy in `cccc-common.sh`, process lifetime enforcement in a dependency-free Python helper, and exercise both wrappers through fake Claude/Codex binaries in disposable Git repositories. Keep `SKILL.md` concise and route detailed procedures into references.

**Tech Stack:** Bash 3.2+, Python 3 standard library, Git, YAML/Markdown, GitHub Actions on Ubuntu/macOS/Windows Git Bash.

---

## Execution rules

- Work only in the `agent/cccc-v2-hardening` worktree.
- Follow red-green-refactor for every behavior change: add one focused failing assertion, run it and observe the intended failure, make the smallest implementation change, rerun the focused test, then run the full local suite.
- Never invoke real Claude or Codex from unit tests. Put deterministic fake executables first on `PATH` and record every argv entry one per line.
- Never auto-commit, stash, reset, clean, push, or modify a user's existing skill installation.
- Keep Bash compatible with macOS Bash 3.2: no associative arrays, `mapfile`, `readarray`, or `${var,,}`.
- Before each task commit, inspect `git diff --check`, `git status --short`, and the exact staged diff.

## Public wrapper contract

Both wrappers accept exactly `<claude|codex> <card-relative-path> [workdir]`; target auto-detection is removed. The environment contract is fixed before implementation:

| Variable | Default | Validation and mapping |
|---|---|---|
| `CCCC_MODE` | `auto` for delegate | `edit`, `auto`, or `full`; consult rejects it because consult has one read-only policy |
| `CCCC_TIMEOUT` | delegate `3600`, consult `1800` | decimal seconds; `0` is explicit unlimited mode; values above the helper's printed cross-platform safe maximum fail before child launch |
| `CCCC_MODEL` | unset | non-empty value maps to Claude `--model VALUE` or Codex `--model VALUE`; unset inherits the configured CLI default |
| `CCCC_EFFORT` | unset | Claude accepts `low|medium|high|xhigh|max` and maps to `--effort VALUE`; Codex accepts `minimal|low|medium|high|xhigh` and maps to `-c model_reasoning_effort=VALUE` |
| `CCCC_ALLOW_FULL` | unset | only literal `1` permits delegate `full`; any other non-empty value is invalid |
| `CCCC_ALLOW_DIRTY` | unset | only literal `1` permits dirty baseline mode; any other non-empty value is invalid |
| `CCCC_CODEX_CONFIG_MODE` | `strict` | consult-only `strict|inherit` |
| `DELEGATE_DEPTH` | `0` | internal recursion guard; decimal only, and any value at least 1 exits 3 |

For v1 migration, `DELEGATE_SANDBOX`, `DELEGATE_TIMEOUT`, and `DELEGATE_MODEL` remain deprecated fallbacks only when the corresponding `CCCC_*` variable is unset; each use prints a migration warning. New and legacy values must never be merged ambiguously.

Wrapper exits are also fixed: `0` success, `2` invalid configuration/path/card, `3` accidental-recursion guard, `4` Git precondition or post-run policy violation, `5` missing/unsafe/colliding output or safe-publication failure, `70` child CLI nonzero (with its original status recorded), `124` wrapper-enforced timeout with successful process cleanup, `125` timeout/interruption cleanup failure, and `127` missing Git/Python/target CLI. A child that naturally exits 124 maps to 70 because the timeout helper's stderr marker is absent.
