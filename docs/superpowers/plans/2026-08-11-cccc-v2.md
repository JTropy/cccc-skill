# cccc v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task.

**Goal:** Ship a standards-compliant, testable cccc v2 skill whose delegate and consult wrappers have safe defaults, fresh atomic outputs, reliable timeouts, and an explicit v1 migration path.

**Architecture:** Keep the installable skill entirely under `skills/cccc/`. Put cross-wrapper validation and Git policy in `cccc-common.sh`, process lifetime enforcement in a dependency-free Python helper, and exercise both wrappers through fake Claude/Codex binaries in disposable Git repositories. Keep `SKILL.md` concise and route detailed procedures into references.

**Tech Stack:** Bash 3.2+, Python 3 standard library, Git, YAML/Markdown, GitHub Actions on Ubuntu/macOS/Windows Git Bash.

---

## Execution rules

- Work only in the `agent/cccc-v2-hardening` worktree.
- Follow red-green-refactor for every behavior change: add one focused failing assertion, run it and observe the intended failure, make the smallest implementation change, rerun the focused test, then run the full local suite.
- Never invoke real Claude or Codex from unit tests. Put deterministic fake executables first on `PATH` and record every argv entry one per line.
- Never auto-commit, stash, reset, clean, push, or modify a user's existing skill installation.
- Keep Bash compatible with macOS Bash 3.2: no associative arrays, `mapfile`, `readarray`, or `${var,,}`.
- Before each task commit, inspect `git diff --check`, `git status --short`, and the exact staged diff.

## Task 2: Implement portable process timeouts

**Files:**

- Create: `skills/cccc/scripts/run-with-timeout.py`

**Step 1: Write failing process-lifetime tests**

Cover argument validation, normal exit propagation, stdout/stderr preservation, `0` as explicit unlimited mode, timeout status 124, TERM cleanup, KILL escalation for a TERM-ignoring child, and a child that naturally returns 124.

The interface is:


The timeout case must emit a unique marker to stderr so wrappers can distinguish it from a child that itself returns 124:

```text
cccc-timeout: command exceeded 1 seconds
```

**Step 3: Implement with Python standard library only**

Required behavior:

- reject missing `--`, empty commands, negative/non-integer seconds with exit 2;
- on POSIX use `start_new_session=True`, `os.killpg(..., SIGTERM)`, wait two seconds, then `SIGKILL`;
- on Windows use `CREATE_NEW_PROCESS_GROUP`, then `terminate()` and `kill()`;
- forward the child's stdout/stderr directly;
- return the child's status when it exits before the deadline;
- return 124 only for wrapper timeout and print the marker.

## Task 4: Rebuild delegate with enforceable policy

**Files:**

- Create: `skills/cccc/scripts/delegate.sh`
- Create: `tests/test_delegate.sh`

**Step 1: Add failing argv and policy tests**

Use the fake agents to cover both targets and all modes:

| Target/mode | Required argv |
|---|---|
| Claude/edit | `--permission-mode acceptEdits` |
| Claude/auto | `--permission-mode auto` |
| Claude/full | `--dangerously-skip-permissions` |
| Codex/edit | `exec --sandbox workspace-write -c sandbox_workspace_write.network_access=false` |
| Codex/auto | `exec --sandbox workspace-write --approve-for-me -c sandbox_workspace_write.network_access=true` |
| Codex/full | `exec --dangerously-bypass-approvals-and-sandbox` |

Assert `full` fails unless `CCCC_ALLOW_FULL=1`. Assert empty `CCCC_MODEL`/`CCCC_EFFORT` adds no override and explicit values add the target's supported flags.

Add policy tests for:

- dirty worktree rejected by default and admitted with a loud warning only under `CCCC_ALLOW_DIRTY=1`;
- missing/invalid `cccc-allowed-paths` rejected before launching an agent;
- fresh report is atomically published next to the task card;
- existing report/log, including symlinks and FIFOs, are refused and their referents remain unchanged;
- agent nonzero, empty report, timeout, HEAD change, and out-of-policy diff all return nonzero;
- a stale report never satisfies a new invocation;
- simultaneous task IDs use independent temporary outputs;
- no wrapper path calls `git commit`, `stash`, `reset`, `checkout`, `clean`, or `push`.

Use task-card-derived outputs `<stem>-report.md` and `<stem>.log`; refuse overwrites rather than silently versioning them.

**Step 2: Run RED**

```bash

```

Expected: canonical delegate wrapper is absent or lacks the new contract.

**Step 3: Implement the wrapper**

Execution sequence:

1. Validate target, depth, timeout, sandbox mode, repo, clean state, card, allowed paths, and output targets.
2. Create a private run directory and capture pre-run HEAD/status.
3. Set `DELEGATE_DEPTH=1` only for the child.
4. Build argv arrays without `eval`; launch through the Python timeout helper.
5. Capture the target's final answer directly into the unique run directory. For Codex use `--output-last-message`; for Claude redirect its print-mode stdout.
6. Capture post-run HEAD/status and verify HEAD unchanged plus every newly changed path is allowed.
7. Require a non-empty regular report; write metadata and captured stderr into the unique log.
8. Publish report and log atomically only after all checks pass.
9. Return a wrapper-specific nonzero status on policy failure while preserving `agent_rc` in the log/error message.

When `CCCC_ALLOW_DIRTY=1`, calculate only the delta from the pre-run snapshot; never claim this prevents an agent from modifying a pre-existing dirty file undetectably. Print that limitation.

Include objective, context, acceptance checks, human-readable boundaries, and the exact machine-readable block:
